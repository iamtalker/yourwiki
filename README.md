# 유어위키 (YourWiki)

누구나 자기 컴퓨터에서 **나무위키의 모든 글(문서 약 180만 개)** 을 가진 위키를 원터치로 띄울 수 있게 해 주는 도구입니다.
편집·추가·삭제가 되는 진짜 위키이고, 나무위키 최신판으로 문서를 갱신할 수도 있습니다.
데이터는 공개 보존처(archive.org, 안 되면 Hugging Face)에서 키트가 직접 받아 옵니다. 제작자는 서버를 운영하지 않습니다.

> 유어위키는 나무위키 운영사와 관계없는 비공식 도구입니다. "나무위키" 이름과 로고를 사이트 이름으로 쓰지 마세요.

## 사용법 (Windows)

1. 이 폴더를 원하는 곳에 둡니다. 디스크 여유 공간이 **45GB 이상** 필요합니다(받는 파일 5.4GB, 설치 후 약 35~40GB).
2. **`유어위키.bat`** 을 더블클릭하면 브라우저에 **관리판**이 열립니다(처음엔 필요한 도구를 먼저 받습니다).
3. 관리판에서 **[설치]** 를 누릅니다. 받기·변환·검색 색인까지 1~2시간 걸립니다. 끊겨도 다시 누르면 이어서 합니다.
4. **[켜기]** → "위키 준비됨"이 뜨면 **[위키 열기]**. 오랜만에 켤 때는 준비에 몇 분 걸릴 수 있습니다.
5. 끌 때는 **[끄기]** 를 누른 뒤 관리판 창을 닫으세요. 그냥 닫았더라도 다음에 관리판을 열 때 남은 프로그램을 자동으로 정리합니다.

관리판에서 고른 설정은 재시작해도 그대로입니다(`panel.json`). 위키를 켜 둔 채 끝냈으면 다음에 관리판을 열 때 다시 켜집니다.
관리판은 기능별 칸으로 접혀 있고, 제목을 누르면 펼쳐집니다.

- **데이터**: 2026-08 나무위키를 나무마크로 되돌린 것(약 180만 개). 가장 많이 쓰이는 틀은 `[include]` 로 되접혀 있습니다(2.0 데이터).
- **동기화**: 끄기 / 요청한 문서만 / **자동 따라잡기(기본: 위키가 켜져 있는 동안 나무위키 최근 변경을 따라감)**.
  위키의 각 문서 위쪽 「🔄 나무위키 최신판으로 갱신」 단추를 누르면 그 문서를 나무위키에서 새로 받아 옵니다.
  robots.txt 를 지키고 6초에 1건 이하로만 요청하며, 캡차·차단이 보이면 즉시 멈춥니다. 같은 문서는 24시간에 한 번만 받습니다.
- 명령줄에 익숙하면 `scripts\install.ps1`(설치), `scripts\start.ps1`·`stop.ps1`(켜기·끄기)을 직접 실행해도 됩니다.

설치 후에는 인터넷 없이도 동작하고, 문서를 볼 때 외부 서비스에 접속하지 않습니다.
openNAMU 가 원래 CDN·유튜브·트위터 등에서 불러오던 것을 중계 서버(`scripts/offline_proxy.py`)가
동봉 파일(`assets/`)로 바꾸거나, 영상·SNS 삽입은 "▶ ○○에서 보기" 링크로 바꿉니다
(누를 때만 외부로 연결). 문서 원문은 바뀌지 않습니다.

설치 마지막 단계에서 검색 색인을 만듭니다. 문서가 많아(2026판 약 180만 개) 수십 분 걸리고 CPU 를 많이 씁니다.

| openNAMU (위키 엔진, BSD-3) | github.com/openNAMU | SHA-256 |

받을 곳과 해시는 `sources.json` 에 있습니다. 더 새로운 덤프가 공개되거나 보관처가 바뀌면
여기에 한 줄 추가하면 됩니다(`"type": "http"`, 또는 토렌트를 쓰려면 `"type": "torrent"` 와 `select_file`).
위에서부터 차례로 시도하고, 어느 경로로 받든 같은 해시로 검증합니다.

## 라이선스와 저작자 표시

> **이 데이터는 CC BY-NC-SA 2.0 KR입니다. 상업적 이용은 금지됩니다.
> 이 키트를 사용해 광고를 붙이거나 상업적으로 운영하는 것은 라이선스 위반입니다.**

- 문서 텍스트: **CC BY-NC-SA 2.0 KR**. 저작권은 각 문서의 기여자에게 있습니다.
  키트는 모든 문서 끝에 원 나무위키 주소, 기여자 목록, 라이선스 고지를 자동으로 넣습니다.
  - **BY**: 원 문서 주소와 기여자를 지우지 마세요.
  - **NC**: 영리 목적으로 쓸 수 없습니다. 키트에는 광고 기능이 없습니다.
  - **SA**: 이 데이터로 만든 결과물도 같은 라이선스로 공개해야 합니다.
- 넘겨주기 문서에는 본문을 바꾸지 않기 위해 고지를 넣지 않습니다.

## 알려진 한계

- **기본 데이터 이후의 변경은 갱신기로 따라잡습니다.** 2026판은 2026-08-29 까지의 내용이고, 그 뒤는 동기화(6초에 1건)와
  P2P 공유로 채워 갑니다. 문서가 많아 전부 따라잡는 데는 오래 걸립니다.
- **틀은 2.0 데이터부터 일부가 되접혀 있습니다.** 문서에는 틀이 이미 펼쳐진 채 들어 있었는데, 2.0 데이터는 가장 많이 쓰이는 틀(스포일러·토막글·상위 문서·상세 내용·문서 가져옴 등 2,324종)을
  `[include(틀:이름)]` 로 되돌려 두었습니다(문서 27%). 틀을 고치면 그 틀을 쓰는 문서가 같이 바뀝니다. **openNAMU 는 한 문서에서 `[include]` 를 5개까지만 렌더링**하므로
  문서마다 되접은 곳은 최대 5개이고, 편집할 때 틀 호출을 6개 넘게 쓰면 6번째부터 보이지 않습니다. 나머지 틀은 아직 펼쳐진 채입니다.
- **틀 문서가 일부만 있습니다.** 덤프에는 일반 문서 위주로 들어 있습니다. 그래서 키트는
  알파위키(나무위키 포크)의 2023-01-04 비공식 덤프에서 뽑은 틀 3,522개(`extras/`)를 보충으로 넣습니다.
  빠진 틀이 쓰인 자리의 약 51%가 이것으로 채워집니다. 틀의 저작자 표시는 틀 원문의 주석(`##`)과
  편집 역사에 남깁니다(본문에 표시하면 그 틀을 쓰는 모든 문서에 끼어들기 때문).
  보충 틀을 원하지 않으면 `scripts\install.ps1 -NoExtras` 로 설치하세요.
- **이미지가 없습니다.** 텍스트만 다룹니다. 나무위키 이미지는 대부분 CC 라이선스가 아닙니다.

## Docker로 서버에 올리기 (베타)

```bash
git clone https://github.com/iamtalker/yourwiki && cd yourwiki
docker compose up -d                 # 처음엔 데이터 받기·설치로 1~2시간
docker compose logs -f               # 진행 확인
```

- 설정은 환경 변수로 바꿉니다: `PORT`(바깥 포트, 기본 3000), `SYNC`(auto/queue/off), `COLOR`(머리글 색), `EDITION`(비우면 기본 데이터판),
  P2P 관련(`P2P`, `P2P_OPEN` 등, 아래 P2P 절), `UPDATE_NOTICE`. 예) `PORT=8080 SYNC=queue docker compose up -d`
- 위키 DB와 받은 데이터는 `./yourwiki-data/` 에 저장되어, 컨테이너를 지우거나 새 버전으로 바꿔도 남습니다.
- 공개 전에 할 일(관리자 가입, 편집 권한, HTTPS)은 아래 리눅스 절과 같습니다.

## 리눅스 서버에 설치하기 (베타)

서버(보통 리눅스)에 올리려는 사람을 위한 스크립트가 `server/` 에 있습니다. 윈도우에서 **`서버설치가이드.bat`** 을 누르면 이 안내를 보기 좋게 정리한 페이지가 열립니다.
필요한 것: python3(3.8 이상), 7z(p7zip-full), curl, 디스크 45GB 이상.

```bash
git clone https://github.com/iamtalker/yourwiki yourwiki-kit && cd yourwiki-kit
bash server/install.sh                  # 엔진·데이터 받기, 해시 검증, 문서 넣기 (끊겨도 다시 실행하면 이어서)
bash server/yourwiki.sh start           # 켜기 (0.0.0.0:3000, 나무위키 동기화 자동)
bash server/yourwiki.sh status          # 상태
sudo bash server/yourwiki.sh install-service   # 부팅 때 자동 시작(systemd)
```

- 바깥 주소·동기화는 환경 변수로 바꿉니다: `LISTEN=127.0.0.1:3000 SYNC=queue bash server/yourwiki.sh start`.
  한 번 준 값은 `yourwiki.conf` 에 기억되어 다음부터 그냥 `start` 해도 그대로입니다(systemd 서비스도 이 파일을 따름).
- 처음 켤 때 검색 색인을 만드느라 오래 걸리고 CPU 를 많이 씁니다. 그동안에도 문서는 볼 수 있습니다.
- HTTPS 는 nginx·Caddy 같은 역방향 프록시를 3000번 앞에 두면 됩니다.
- 첫 가입자가 관리자가 됩니다. 공개 전에 편집 권한(누구나/가입자만/읽기 전용)을 관리자 설정에서 정하세요.
- 이 스크립트들은 아직 실제 리눅스 서버에서 충분히 시험하지 않았습니다. 문제가 있으면 이슈로 알려 주세요.

## P2P 공유 (1.2, 베타) — 서버 없이

갱신기는 나무위키 서버 부담 때문에 6초에 1건만 받아서, 덤프 이후 바뀐 문서를 따라잡는 게 가장 느린 부분입니다.
관리판의 **P2P 공유**를 켜면 참여한 유어위키끼리 나무위키에서 받은 문서를 나눠 갖습니다. **누구의 서버도 필요 없습니다.**

- 각 위키는 대기열을 무작위 순서로 받고, 친구나 검증된 ID 가 이미 받은 문서는 건너뜁니다. 그래서 서로 다른 문서를 받아 나누고,
  참여자가 N곳이면 전체로는 약 N배 빠르게 따라잡습니다. 위키마다 나무위키로 가는 요청(6초에 1건)은 그대로입니다.
- **켜 두기만 하면 됩니다**(BitTorrent 처럼): 아래의 '유어위키 게시판'으로 서로 모르는 위키끼리도 알아서 찾아 주고받습니다. 친구를 적을 필요가 없습니다.
- **ID**: 각 위키는 처음 켤 때 서명 열쇠(Ed25519)를 만들고 공개 열쇠가 ID 가 됩니다(`wiki/p2p_key.json`, 남에게 주지 마세요).
  친구 ID 는 선택입니다. 적어 두면 그 위키가 준 문서는 수습 기간 없이 바로 믿고 받습니다.
- **P2P 창구**: 켜면 내 위키가 작은 읽기 전용 창구(3002번)를 열고, 그 창구만 바깥에 엽니다(방법은 아래 '창구 여는 방법', 기본은 Cloudflare 임시 주소).
  창구로는 서명된 문서 묶음만 나가고 **위키 화면은 공개되지 않습니다**(위키를 공개하는 [공개하기]와 별개).
- **서로 찾기**: '내 ID → 지금 창구 주소'를 **BitTorrent 공용 연결망(DHT)** 에 내 열쇠로 서명해 올려 둡니다(BEP 44). 토렌트 프로그램들이 전 세계에서
  함께 운영하는 연결망이라 누구의 관리도 필요 없습니다. 다른 위키는 내 ID 로 지금 주소를 찾아오므로 주소가 바뀌어도 됩니다.
- **유어위키 게시판**: DHT 안에 모든 유어위키가 같은 열쇠로 읽고 쓰는 공용 칸 8개가 있습니다(최근 위키 200곳). 각 위키는 가끔 아무 칸에
  자기 ID 를 적고, 칸들을 읽어 모르는 위키를 알아냅니다. 칸에는 ID 만 있고 주소는 각 ID 가 자기 열쇠로 서명한 기록에서만 얻으므로,
  누가 칸을 가짜 ID 로 채워도 주소를 속일 수 없고 찾기가 조금 늦어질 뿐입니다(시험: 가짜 ID 800개로 도배해도 몇 분 안에 서로 찾음).
  주소를 한 번도 찾지 못한 ID 는 점점 뜸하게 찾다가 잊습니다.
- **소개받기**: 실제로 연결된 위키가 '최근 주고받은 위키'로 적어 둔 ID 는 게시판의 ID 보다 먼저 찾아갑니다.
- **대신 전하기**: 받아서 서명을 확인한 남의 묶음도 내 창구에 두어 다시 나눠 줍니다. 원래 위키가 꺼져 있어도 켜져 있는 누군가를 거쳐 퍼집니다.
  서명과 해시 때문에 중간에 거친 창구는 내용을 바꾸지 못합니다.
- **창구 여는 방법**(관리판 P2P 칸의 고급 설정, 리눅스·Docker 는 `P2P_OPEN`):
  - **Cloudflare 임시 주소**(기본, `tunnel`): 공유기 설정이 필요 없고 내 IP 가 보이지 않습니다. 대신 Cloudflare 의 무료 빠른 터널에 기댑니다.
  - **직접 연결**(`direct`): Cloudflare 없이 엽니다. 컴퓨터에 공인 IP 가 바로 있으면 그대로, 아니면 공유기 포트를 자동으로 빌리고(UPnP, 1시간씩 연장, 끌 때 돌려줌),
    공인 IPv6 가 있으면 그것도 씁니다. **내 공인 IP 가 다른 참여자에게 보입니다**(BitTorrent 와 같음). 통신사 공유 IP(CGNAT)에서는 안 됩니다.
  - **둘 다**(`both`): 직접 주소를 먼저, Cloudflare 주소를 두 번째로 올립니다. 첫 주소에 닿지 않는 위키는 두 번째로 넘어갑니다.
  - 어느 쪽도 안 되면 받기는 그대로 되고 나눠 주기만 안 됩니다. Docker 에서 직접 연결은 `network_mode: host` 일 때만 됩니다.
- 한계: 공용 연결망(UDP)을 막는 회사·학교 네트워크에서는 P2P 가 안 됩니다(위키는 그대로 동작).
  처음 보는 위키들에게서는 검증이 쌓일 때까지 조금씩만 받습니다(아래 사보타주 방지).
- 리눅스·Docker: `P2P=on` 이면 됩니다(리눅스는 한 번 준 설정을 `yourwiki.conf` 에 기억해 다음부터 그냥 `start` 해도 그대로). 친구는 선택 `P2P_FRIENDS=ID1,ID2`. 창구로 오는 고정 주소가 있으면 `P2P_URL=https://…`(없으면 임시 주소 자동).

### 사보타주 방지

누군가 문서를 난수나 거짓 내용으로 바꿔 "최신판"이라며 퍼뜨리는 경우를 막습니다. **믿음은 주소가 아니라 ID 의 검증 실적으로만 쌓입니다.**

- **등급**: 친구(내가 적은 ID) · 검증된 ID(검증 5건 통과, 거짓 0건) · 수습 ID(그 밖).
- **검증**: 갱신기가 나무위키 요청의 20%로, P2P 로 받은 문서를 나무위키에서 직접 다시 받아 맞춰 봅니다(수습 ID 것부터).
  같은 수정 시각에 내용이 다르면 거짓이 확실하므로 그 ID 를 **차단**하고, 그 ID 에게서 받은 문서를 **모두 받기 전으로 되돌린 뒤**
  다시 받을 목록에 넣습니다(친구도 예외 없음).
- **ID 를 새로 만들어도 소용없게**: 새 ID 는 실적이 0 이라 수습부터 다시 시작합니다. 수습 ID 들에게서는 **모두 합쳐** 한 시간에 200개까지만 받으므로,
  공격자가 ID 를 1,000개 만들어도 퍼질 수 있는 양은 늘지 않습니다. 중계소도 처음 보는 ID 를 한 시간에 200개까지만 받습니다.
- **큰 변경은 직접 확인**: 내 문서와 절반 넘게 다른 내용(예: 통째로 난수로 바꾼 문서)은 P2P 로 받지 않고 나무위키에서 직접 받습니다.
- 서명이 맞지 않는 묶음, 미래 시각, 변환기 판이 다른 문서(친구 것 제외)는 받지 않습니다. 받은 문서는 역사에 어느 ID 에서 왔는지 남습니다.
- **검증을 피하는 속임수도 막습니다**:
  - 수정 시각을 나무위키의 지금 판보다 늦게 적어 내면(있을 수 없는 판) 거짓으로 보고 차단합니다.
  - 나무위키에 없는 문서(404)를 준 경우 그 문서를 되돌리고, 수습 ID 가 3번 그러면 차단합니다.
  - 남이 올린 정직한 묶음을 자기 ID 로 다시 서명해 올려도 실적은 **처음 올린 ID** 에게만 쌓입니다(실적 가로채기 방지).
  - 같은 판을 다른 때 받아 서식만 조금 다른 경우는 낱말 단위로 비교해 통과시킵니다(정직한 친구를 잘못 차단하지 않게).
- 시각 비교는 나무위키 시각(한국 표준시) 기준이라 중계소·서버가 UTC 여도 됩니다.
- 한계: 검증되기 전 잠깐은 한 줄짜리 조작 같은 작은 거짓이 보일 수 있습니다(수습 한도로 양을 묶고, 검증에 걸리면 되돌립니다).

### 중계소 (선택)

없어도 되지만, 누군가 항상 켜져 있는 고정 주소 서버가 있다면 중계소를 띄워 모두의 속도와 연결성을 높일 수 있습니다.
중계소도 서명과 해시를 바꾸지 못하므로 누가 운영하든 안전합니다. 관리판의 '중계소 주소'에 적으면 거기로도 보내고 받습니다.

- 위키 없이 중계소만: `python3 scripts/hub_server.py --listen 0.0.0.0:8080` (파이썬 3.8 이상). 리눅스 서버(예: Oracle Cloud 무료)에 한 줄 설치:
  `sudo bash server/hub-setup.sh`(서비스 등록, 방화벽 열기). 클라우드 콘솔의 방화벽에서도 그 포트를 열어야 합니다.
- 위키와 함께: Docker·리눅스에서 `HUB=on` 이면 위키 주소의 `/_hub/` 가 중계소가 됩니다.
- 내 ID 보기: `python scripts/p2p.py wiki --id` (관리판에도 표시).

## 내보내기 · 가져오기

관리판의 **내보내기**에서 위키를 파일로 만들어 `export/` 폴더에 저장합니다. 진행 중에는 남은 시간을 보여 줍니다.

- **범위**(내보내기·가져오기 공통, 고른 값은 기억됨): **전체 문서** 또는 **설치한 판(예: 2026-08) 이후 바뀐 문서만**
  (갱신기·P2P·직접 편집으로 생긴 판. 덤프에서 온 판은 빠짐). '이후 바뀐 문서만'은 파일이 작아 다른 사람에게 나눠 주기 좋습니다.
- **유어위키(openNAMU)**: `yourwiki-opennamu-….db` — openNAMU 의 `data.db` 와 같은 SQLite. 문서 표(data·history·data_set·back)만 담고
  사용자 계정·접속 기록·토론은 넣지 않습니다. 변환이 없어 빠르고, '전체'로 내보낸 파일은 새 openNAMU 의 `data.db` 로 그대로 써도 됩니다.
- **MediaWiki**: `yourwiki-mediawiki.xml.gz` → `php maintenance/run.php importDump --report 파일`.
  분류는 `Category:`, 틀은 `Template:`(인자 `@이름@` → `{{{이름}}}`)으로 옮깁니다. 표·접기·문법 강조에는 MediaWiki 기본 확장
  (SyntaxHighlight, Math)과 `mw-collapsible` 을 씁니다.
- **DokuWiki**: `yourwiki-dokuwiki.zip` → DokuWiki 폴더에 `data/` 를 덮어 풀고 `php bin/indexer.php`. 분류와 틀은 이름공간으로,
  파일 이름은 DokuWiki 기본 설정(`fnencode = url`)에 맞춥니다.
- **Markdown**: `yourwiki-markdown.zip` → 문서마다 `.md` 하나(GitHub 방식). 모두 한 폴더라 문서 사이 링크가 그대로 이어지고,
  Obsidian 같은 편집기에서 폴더째 엽니다. 합친 칸이 있는 표는 HTML 표, 접기는 `<details>`, 각주는 `[^1]` 로 옮깁니다.
- MediaWiki·DokuWiki·Markdown 은 CPU 여러 개로 나눠 변환합니다. 전체 문서(약 180만 개)는 CPU 4개 PC 기준 약 1시간, 디스크 3~10GB.
  이미지와 `#!html` 은 옮기지 않고, 틀 문법은 엔진마다 달라 일부는 손으로 고쳐야 할 수 있습니다.
- 모든 문서 끝의 출처·라이선스 고지는 그대로 옮겨집니다. 내보낸 데이터도 **CC BY-NC-SA 2.0 KR** 이니 지우지 마세요.

**가져오기 (openNAMU 형식)**: 받은 파일(유어위키가 내보낸 것이나 다른 openNAMU 의 `data.db`)을 유어위키 폴더의 `import/` 에 넣고,
위키를 끈 뒤 관리판의 **가져오기**에서 고릅니다.
- 문서마다 내 쪽보다 새 판만 역사 뒤에 이어 붙이고, 내 쪽이 같거나 더 새로우면 건너뜁니다(지우기는 옮기지 않음).
  가져온 판의 역사 요약에는 `[가져옴 파일이름]` 이 붙습니다.
- **검증**: '나무위키 최신판' 이라고 적힌 판(갱신기·P2P 판)은 P2P 로 받은 문서처럼 갱신기가 틈틈이 나무위키와 맞춰 봅니다(동기화가 켜져 있을 때).
  하나라도 거짓이면 그 파일에서 가져온 문서를 모두 되돌리고 나무위키에서 다시 받습니다. 직접 편집한 판은 나무위키와 비교할 수 없어 검증하지 않으니,
  믿을 수 있는 곳에서 받은 파일만 넣으세요.

명령줄:
- `python scripts/wiki_pack.py export wiki [--range changed]`, `python scripts/wiki_pack.py import wiki 파일.db [--range changed]`
- `python scripts/convert_wiki.py wiki --to mediawiki|dokuwiki|markdown [--range changed] [--out 파일] [--jobs CPU수]`

## 새 판 알림

관리판은 12시간에 한 번 GitHub(`iamtalker/yourwiki`)의 **최신 릴리스**를 확인해, 새 판이 나오면 맨 위에 알려 줍니다(릴리스 링크와 달라진 점).
**알리기만 하고 스스로 설치하지 않습니다.** 서로 연결된 위키들은 한번 퍼진 판을 누가 대신 되돌려 줄 수 없으므로, 받을지는 각자 릴리스 내용을 보고 정합니다.
보내는 정보는 없고, GitHub 가 안 되면 조용히 넘어갑니다. 관리판의 '새 판 알림'에서 끌 수 있고, 리눅스·Docker 는 `UPDATE_NOTICE=off`.
명령줄: `python scripts/update_check.py`. 확인할 저장소는 `sources.json` 의 `update.repo`.

## 인터넷에 공개하려면

- **간단히**: 관리판의 **인터넷에 공개 → [공개하기]**. 공유기 설정 없이 Cloudflare 임시 주소(https)가 생깁니다. 켤 때마다 주소가 바뀌고,
  [공개 끄기]를 누르기 전까지는 위키를 켤 때마다 다시 공개됩니다.
- **직접**: `panel.json` 의 `listen` 을 `0.0.0.0:3000` 으로 바꾸거나(`scripts\start.ps1 -Listen 0.0.0.0:3000`) 리눅스·Docker 로 서버에 올립니다.

공개하는 순간 **그 사이트의 운영 책임은 공개한 사람에게** 있습니다(권리 침해·게시중단 요청 대응 등).
"나무위키" 이름과 로고는 쓰지 마세요. 콘텐츠 라이선스와 상표는 별개입니다.

## 삭제 요청·권리 침해 신고를 받았을 때

이 프로젝트(코드)는 문서를 호스팅하지 않습니다. 문서는 각 사용자의 컴퓨터에만 있고, 데이터 묶음은 외부 보관처(archive.org, Hugging Face)가 호스팅합니다.

- **내 위키를 공개했다면**: 그 사이트의 운영자는 공개한 사람입니다. 신고를 받으면 해당 문서를 위키에서 지우세요(관리자 → 문서 삭제).
  지워도 P2P·갱신기가 나무위키에서 다시 받아 올 수 있으니, 그 문서 제목은 갱신 대기열에서도 빼고 필요하면 동기화를 끄세요.
- **연락처를 위키에 적어 두세요.** 공개하기 전에 첫 화면 등에 삭제·권리 침해 요청을 받을 연락처를 적는 것을 권합니다.
- **키트 제작자에게 온 요청**: 키트는 코드이고 문서를 가지고 있지 않아 지울 수 있는 것이 없습니다. 보관처의 데이터 묶음에 대한 요청은 그 보관처의 절차를 따릅니다.
- 이 안내는 법률 자문이 아닙니다. 큰 규모로 운영하기 전에는 전문가에게 확인하세요.
