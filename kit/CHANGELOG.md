# 변경 기록

버전마다 달라진 점을 여기에 적습니다. 새 버전이 위에 옵니다.

## 2.1.0 — 2026-10-03

**폴더 구조를 정리했습니다. 최상위에는 `유어위키.exe`·`서버설치가이드.html`·`kit`(·설치하면 `wiki`)만 보입니다.**
- 프로그램·도구·설정·기록은 모두 `kit/` 안으로 들어갔습니다. 위키 데이터 `wiki/` 는 **kit 밖, 실행 파일 옆**에 있어서, 위키를 옮기거나 백업할 때는 `wiki` 폴더만 복사하면 됩니다. 새 판으로 바꿀 때도 `kit` 과 `유어위키.exe` 만 바꾸고 `wiki` 는 그대로 둡니다.
- `유어위키.bat` 을 **`유어위키.exe`**(파란 바탕의 흰 Y 아이콘)로 바꿨습니다. 창 없이 관리판만 띄우고, 도구가 없는 처음 한 번만 받는 과정을 창으로 보여 줍니다. 소스는 `kit/launcher/Launcher.cs`, 빌드는 `kit/launcher/build.ps1`(윈도우 기본 C# 컴파일러)입니다. 서명하지 않은 프로그램이라 Windows 가 처음에 "알 수 없는 게시자"로 경고할 수 있습니다.
- `서버설치가이드.bat` 을 없애고, 가이드 페이지(`서버설치가이드.html`)를 최상위에 바로 뒀습니다.
- 배포 zip 에는 `README.md`·`CLAUDE.md`·`AGENTS.md`·`.gitignore` 같은 저장소 전용 파일과 시험·개발 기록(`kit/tests`, `kit/refold`, `kit/README_FOR_AI.md`)을 넣지 않습니다. GitHub 첫 화면 `README.md` 는 짧은 소개이고, 자세한 설명서는 `kit/README.md` 입니다.
- 리눅스·Docker: 명령이 `bash kit/server/install.sh`, `bash kit/server/yourwiki.sh start`, `cd kit && docker compose up -d` 로 바뀝니다(스크립트가 `kit/wiki` 를 최상위 `wiki` 로 이어 줍니다).
- 설치 스크립트는 파이썬·aria2 압축 파일을 풀 때만 받고 풀고 나면 지웁니다(용량 10MB 남짓 절약). 관리판의 다른 폴더 위키 알아보기도 새 구조를 알아봅니다(옛 구조 폴더도 알아봄).
- 위키 첫 화면 문구와 설명서의 `유어위키.bat` 표현을 `유어위키.exe` 로 바꿨습니다.
- **2.0 이하에서 올라오는 분**: 옛 폴더에 덮어쓰지 말고, 새 압축 파일을 **새 폴더에** 풀어 옛 폴더의 `wiki` 폴더만 옮기세요. 자세한 방법은 `kit/README.md` 의 「폴더 구조, 옮기기, 새 판으로 바꾸기」입니다.

## 2.0.3 — 2026-10-03

**위키 켜는 시간을 수 분 → 1초 안팎으로.**
- 원인: openNAMU 는 켤 때마다 모든 표의 모든 열에 `select count(*) … where 열 is null` 검사를 돌립니다. 문서 표(`data`)는 본문이 커서 이 검사가 열마다 표 전체를 읽었습니다(시작할 때 약 14GB, 디스크가 식어 있으면 몇 분).
- 해결: 비어 있는 부분 색인(`where 열 is null`)을 만들어 검사가 색인만 보고 끝나게 했습니다(`scripts/fast_start.py`). 널 값이 생기면 색인에 들어가므로 검사 결과는 같고, 문서·검색에는 영향이 없습니다.
  설치 때 한 번 만들고(약 20초), 이미 설치한 위키는 [켜기] 때 없으면 한 번 만듭니다. 사용해 보니 엔진이 열리는 데 37초 → 0.6초, 시작 때 읽는 양 14GB → 0 이었습니다.
- 설치 중 색인을 만드는 단계에서 `main.amd64.exe` 가 CPU 를 많이 쓰는 것은 정상이라는 안내를 넣었습니다(끄면 색인을 처음부터 다시 만들어야 합니다).

## 2.0 — 2026-10-03

**틀 되접기: 데이터 판이 새로 나왔습니다(`build20261002`, 5.35GB).**
- 문서에는 틀이 이미 **펼쳐진 채** 박혀 있었습니다. 2.0 데이터는 그 펼쳐진 덩어리 가운데 문서 49만 개(27%)의 69만 곳을 `[include(틀:이름)]` 호출로 **되돌렸습니다.** 틀을 고치면 그 틀을 쓰는 모든 문서가 같이 바뀌는 위키 본래의 편집 구조가 살아납니다. 글자는 3.3% 줄었습니다.
- 대상: 스포일러·토막글·사건사고·교육기관 같은 상자 틀과 둘러보기 틀 2,318종(완전히 같은 덩어리가 20개 문서 이상 반복되고, 2021 공식 덤프의 같은 문서에서 불러 쓴 이름이 일치한 것만),
  그리고 가장 많이 쓰이는 한 줄짜리 매개변수 틀 6종(`틀:상위 문서`·`틀:상세 내용`·`틀:분류 설명`·`틀:관련 문서`·`틀:문서 가져옴`·`틀:문서 가져옴/문단`).
- **원본과 똑같이 보이는지** 빈 openNAMU 에서 접기 전·후를 렌더링해 확인했습니다(무작위 800개 중 798개 동일, 나머지 2개는 접기 전 쪽의 렌더러 버그). 확실하지 않은 것은 접지 않았습니다.
- 알아 둘 점(openNAMU 의 제한): **한 문서에서 `[include]` 는 5개까지만 렌더링됩니다**. 그래서 문서마다 되접은 곳은 최대 5개이고, 편집할 때 틀 호출을 6개 넘게 쓰면 6번째부터 보이지 않습니다.
  틀 안의 `[[분류:…]]` 는 문서에 적용되지 않으므로, 원본에서 적용되던 분류는 틀 호출 뒤에 그대로 남겨 두었습니다.
- 이미 설치한 1.x 위키는 그대로 쓸 수 있습니다. 2.0 데이터를 받으려면 관리판에서 다시 설치해야 합니다(위키 데이터 약 35GB, 받는 파일 5.35GB).
- 도구: `export_dump.py --refolded` 로 되접은 틀을 데이터 판에 넣습니다. 만드는 코드와 기록은 `refold/` 에 있습니다.

## 1.2 — 2026-09-29

**P2P 공유(베타, 서버 없이)**
- 관리판에서 켜면 유어위키끼리 나무위키에서 받은 문서를 나눠 갖습니다. 각 위키가 서로 다른 문서를 받아 나누므로 참여자가 많을수록 빨리 따라잡습니다(위키마다 나무위키 요청 속도는 그대로).
- 서로 찾기: 'ID → 창구 주소'를 BitTorrent 공용 연결망(DHT, BEP 44)에 서명해 올립니다. DHT 안의 '유어위키 게시판'(공용 칸 8개)으로 서로 모르는 위키끼리도 알아서 찾고(친구 ID 는 선택), 소개받은 ID 를 먼저 찾아 가짜 ID 도배를 견딥니다(`scripts/dht.py`).
- 위키마다 서명 열쇠(Ed25519, 표준 라이브러리로 구현)가 ID. 확인한 남의 묶음을 대신 전해 원래 위키가 꺼져 있어도 퍼집니다. 서명·해시 때문에 중간에서 내용을 바꾸지 못합니다.
- 창구 여는 방법: Cloudflare 임시 주소(기본, IP 숨김, `scripts/cloudflared.py`) / 직접 연결(공인 IP·공유기 UPnP·IPv6, `scripts/direct.py`) / 둘 다(주소 두 개, 첫 주소가 안 되면 두 번째로).
- 사보타주 방지: 믿음은 ID 의 검증 실적으로만(검증 5건 통과 → 검증된 ID). 갱신기 요청의 20%로 나무위키와 직접 맞춰 보고, 거짓이면 그 ID 를 차단하고 받은 문서를 전부 되돌림. 수습 ID 들 모두 합쳐 한 시간 200개. 절반 넘게 바뀐 문서는 직접 확인. 미래 수정 시각·나무위키에 없는 문서(404)·남의 묶음 재서명으로 실적 가로채기를 막고, 서식만 다른 경우는 통과. 시각은 한국 표준시 기준.
- 관리판 P2P 칸은 설명과 켜기·끄기, 한 줄 현황만. ID·친구·중계소·창구 여는 방법·상세 현황은 '고급 설정'.
- 중계소(선택): 고정 주소 서버가 있으면 `scripts/hub_server.py`(위키 없이) 또는 `HUB=on`, 한 줄 설치 `server/hub-setup.sh`.
- 리눅스·Docker: `P2P`, `P2P_OPEN`, `P2P_FRIENDS`, `P2P_URL`, `P2P_HUBS`, `HUB` 환경 변수.

**내보내기 · 가져오기**
- 관리판에서 MediaWiki(.xml.gz), DokuWiki(.zip), Markdown(.zip), 유어위키(openNAMU) 형식(.db)으로 내보냅니다(`scripts/convert_wiki.py`, `scripts/wiki_pack.py`). CPU 여러 개로 변환하고 진행률·남은 시간을 보여 줍니다.
- openNAMU 형식은 `data.db` 와 같은 SQLite(문서 표만, 계정·IP 기록 제외). 다른 유어위키·openNAMU 의 파일을 `import/` 폴더에서 가져옵니다(내 쪽보다 새 판만 이어 붙임, 위키를 끈 상태에서만).
- 범위: '전체' 또는 '설치한 판 이후 바뀐 문서만'(내보내기·가져오기 공통, 기억됨).
- 가져온 문서 검증: '나무위키 최신판' 이라고 적힌 판은 P2P 처럼 갱신기가 나무위키와 맞춰 보고, 거짓이면 그 파일에서 가져온 문서를 모두 되돌립니다(P2P 를 꺼도 동기화가 켜져 있으면 검증).

**관리판·설정**
- 기능별 칸을 접어 두고 제목을 누르면 펼침(상태·위키 켜기·끄기만 펼친 채). 접힌 칸 제목 옆에 한 줄 요약.
- 설정 유지: 고른 설정이 재시작 뒤에도 그대로. 저장 중에 꺼져도 날아가지 않음(직전 판 `.bak`). 위키를 켜 둔 채 끝냈으면 다시 켬([공개하기]도 [공개 끄기] 전까지 유지, 주소는 새로 바뀜). 리눅스는 한 번 준 환경 변수를 `yourwiki.conf` 에 기억.
- 새 판 알림: 12시간에 한 번 GitHub 최신 릴리스를 확인해 알려 줌(알리기만, 자동 설치 안 함, `scripts/update_check.py`). 리눅스·Docker 는 켤 때 한 줄로, `UPDATE_NOTICE=off` 로 끔.
- 동기화 대기열을 비우는 데 걸릴 시간 표시. 켜는 중에도 문서 수가 '?' 대신 마지막으로 읽은 수로 보임.
- 진행 표시를 한국어로: 다운로드 도구(aria2)의 영어 진행 표시를 번역하고, 문서 넣기에 전체 대비 진행률과 남은 시간.

**위키 화면·갱신기**
- 휴대폰 화면: 검색줄을 한 줄로, 넓은 표는 옆으로 밀어 보도록, 떠 있는 갱신 단추는 아이콘만, 아래쪽 여백.

**안정성**
